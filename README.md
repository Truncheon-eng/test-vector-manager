# test-vector-manager

Ветка: `uvm-test-vector-manager-posix`. Состояние: `d8ad7a0`.

## Этап разработки

Ветка объединяет переход на POSIX shared memory, передачу фиксированных значений, кольцевой буфер и синхронизацию доступа.

Используются `shm_open`, `ftruncate`, `mmap(MAP_SHARED)`, `munmap` и `close`. При записи и очистке вызывается `msync`. Сериализацию доступа обеспечивает `flock` через RAII-класс `SharedMemoryLock`, а не сам вызов msync.

## Кольцевой буфер и блокировка

Используется `RingBuffer<64, uint32_t>`: очередь на 64 элемента по 32 бита. Псевдоним `RingBufferUint64` в исходниках означает именно этот тип, а не очередь 64-битных чисел.

Счётчики чтения и записи определяют заполненность. Индекс элемента вычисляется маской `SIZE-1`; ёмкость должна быть степенью двойки. Поле magic со значением `0xdeadbeef` позволяет определить необходимость инициализации. Очистка повторно конструирует буфер через placement new.

`SharedMemoryLock` получает эксклюзивную блокировку файлового дескриптора в конструкторе и освобождает её в деструкторе. Прерванные вызовы повторяются при `EINTR`. Блокировка охватывает операции чтения, записи и очистки.

| Код | Значение |
| --- | --- |
| 0 | DPI_SUCCESS |
| 1 | DPI_ERROR |
| 2 | DPI_BUFFER_EMPTY |
| 3 | DPI_BUFFER_FULL |

## Сборка и проверочный сценарий

Нужны GNU Make, g++ с поддержкой C++17, Git и подходящая сборка Verilator/UVM. Makefile не задаёт стандарт C++ явно; компилятор должен поддерживать используемые конструкции в выбранном режиме.

```sh
make build
make run
```

`make build` получает UVM при необходимости, генерирует модель, собирает `out/Vtest_dpi` и `server.out`. `make run` выполняет сборку и запускает UVM-тест.

Тест самостоятельно открывает память, устанавливает размер по `sizeof(RingBuffer<64, uint32_t>)`, очищает буфер, записывает восемь фиксированных значений и проверяет их чтение в исходном порядке. Затем проверяет чтение из пустой очереди и результат очистки. Успешное завершение сопровождается `All checks passed`.

Интерактивный сервер для этого сценария запускать не требуется: тест сам выполняет и запись, и чтение. Параллельные действия сервера могут изменить проверяемую очередь.

## Интерактивный сервер

```sh
make server
./server.out
```

Меню: 0 – запись значения в шестнадцатеричном виде, 1 – чтение, 2 – очистка, 3 – выход. Сервер и DPI-код обращаются к объекту памяти с именем `a.c`.

Другие команды исходного Makefile:

- `make verilate` – генерация C++-модели в `out/`;
- `make clean_server` – удаление `server_obj/` и `server.out`;
- `make clean` – очистка результатов сборки сервера и симуляции.

Закрытие дескриптора и очистка сборки не вызывают `shm_unlink`; объект памяти может переживать запуск процесса.
