# test-vector-manager

Ветка: `uvm-test-vector-manger`. Состояние: `c6d4591`.

## Этап разработки

Добавлена связь SystemVerilog/UVM с C++ через DPI-C. Тест записывает 32-битное значение в разделяемую память и читает его обратно через импортированные функции.

В этой ветке используется **System V**, как и в исходном клиент-серверном примере: `ftok`, `shmget`, `shmat` и `shmdt`.

## Устройство

- `test_dpi.sv` – верхний модуль и UVM-класс `my_test`.
- `dpi_funcs.cpp` – экспортируемые через `extern "C"` функции `write_data` и `read_data`, вспомогательные операции IPC.
- `Makefile` – получение UVM, сборка и запуск Verilator.

При каждой операции C++-код обеспечивает наличие файла `a.c`, получает ключ и подключает сегмент размером 4096 байт. Работа ведётся с одним значением типа int в начале сегмента. После операции сегмент отсоединяется.

## Сценарий

UVM-тест поднимает objection, записывает `32'hDEADBEEF`, читает значение обратно, выводит его и снимает objection. Проверка равенства прочитанного значения ожидаемому и полноценная обработка кодов возврата в этом тесте отсутствуют: журнал служит демонстрацией обмена.

## Запуск

Нужны g++, GNU Make, Verilator с поддержкой используемых UVM-конструкций и Git. Makefile скачивает ветку `uvm-1.2` библиотеки `chipsalliance/uvm-verilator`, если каталог отсутствует.

```sh
make run
```

`make` также запускает тест. Бинарный файл создаётся как `out/Vtest_dpi`.

```sh
make clean
```

Очистка удаляет `out/`, сохраняя UVM. Она не удаляет System V IPC-сегмент. В C++ есть вспомогательная функция удаления, но сценарий теста её не вызывает.

## Граница этапа

Отдельного генератора, очереди и межпроцессной блокировки здесь нет. Переход на `shm_open` / `mmap` находится в следующей ветке, `uvm-test-vector-manager-posix`.

Коммит `9919602`, упомянутый в описании проекта как переход на POSIX, по фактическому `dpi_funcs.cpp` также относится к System V. POSIX-вариант появляется в `caa02da`.
