# test-vector-manager

Ветка: `main`. Состояние: `d5c7431`.

## Назначение и этап разработки

Первый этап разработки менеджера тестовых векторов: изучение Linux IPC на примере двух процессов, обменивающихся строкой через разделяемую память. UVM, DPI-C и кольцевого буфера в этой ветке ещё нет.

Используется System V shared memory: `ftok`, `shmget`, `shmat`, `shmdt`, `shmctl(..., IPC_RMID, ...)`.

## Обмен данными

Сервер создаёт файл `a.c`, используемый для получения ключа IPC, подключает сегмент размером 4096 байт и размещает в нём структуру `block`:

- `read` – признак, что клиент прочитал сообщение;
- `buf[128]` – текст сообщения.

Сервер записывает `Hello world: 0!`, затем ожидает подтверждения чтения. Клиент читает сообщение, устанавливает `read=true` и отсоединяется от сегмента. Сервер увеличивает счётчик и готовит следующее сообщение. При ожидании используется пауза в три секунды.

## Сборка и запуск

Нужны GCC, GNU Make и shell. Процессы запускаются из одного каталога: относительный путь `a.c` должен указывать на один и тот же файл.

```sh
make
./bin/server
```

В другом терминале:

```sh
./bin/client
# Либо повторное чтение каждые три секунды:
sh client.sh
```

После завершения работы остановите сервер и цикл клиента, затем удалите IPC-сегмент:

```sh
./bin/destroy_shm
```

`make clean` удаляет каталоги сборки, но не заменяет удаление IPC-сегмента.

## Структура

- `hdr/shared_memory.h` – структура сообщения, константы и объявления.
- `src/auxiliary_functions.c` – функции работы с IPC.
- `src/server.c`, `src/client.c` – участники обмена.
- `src/destroy_shm.c` – удаление сегмента.
- `client.sh` – повторный запуск клиента.
- `makefile` – сборка бинарных файлов в `bin/`.

## Ограничения этапа

Флаг read не защищён межпроцессным примитивом синхронизации и не является полноценным протоколом безопасного конкурентного доступа. Сервер работает в бесконечном цикле. Этот пример показывает базовый механизм обмена, а не готовый транспорт тестовых векторов.
